# 展图授权清单管理

博物馆数字展览团队使用的网页工具：导入拼版展图与原图的对照关系、分批补录原图授权，
在**每张原图都有有效商用授权且编辑确认署名**后，才能下载列有「原图号、授权号、署名」的清单。
授权被撤回时自动换用同署名有效授权，否则停供并等待编辑确认替代清单。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
```

访问 http://localhost:8000 。SQLite 数据保存在名为 `app-data` 的卷中（容器内 `/data/app.db`），
服务重启、容器重建后状态不丢。

### 本地开发

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
```

数据库路径由环境变量 `EXHIBITION_DB` 指定，默认 `data/app.db`。

## CSV 格式

均支持 UTF-8（含 Excel 的 BOM），列名支持中文或英文别名。

**展图-原图对照 CSV**（首页导入，可重复导入，幂等）：

```csv
展图号,展图名称,原图号
EXH-01,唐代壁画拼版,ORG-001
```

**授权 CSV**（可分批补录）：

```csv
授权号,原图号,是否允许商用,署名
LIC-001,ORG-001,是,摄影：张三
```

「是否允许商用」接受 `是/否/允许/不允许/true/false/1/0` 等取值。
示例数据见 `sample_data/`。

## 功能与规则

- **导入**：对照 CSV 建立展图与原图关系；授权 CSV 分批补录，授权号唯一——
  重复导入的行直接跳过，**重传不能恢复已撤回的授权**。
- **下载条件**：展图的每张原图都有有效（未撤回且允许商用）授权，且编辑已确认署名，
  才可下载清单 CSV（列：原图号、授权号、署名）。下载请求在事务内实时复核，停供返回 409 及原因。
- **当前授权实时解析**：清单不写死授权号，读取时按「已确认署名 → 同署名有效商用授权
  （授权号 id 最小）→ 任一有效商用授权 → 缺授权」解析。因此换证后，展图详情页、
  授权使用情况、确认记录、CSV 下载以及 JSON API 看到的都是同一个当前有效授权号。
- **撤回（网页操作，终态）与递补**：
  - 撤回与同署名递补在**同一事务**内生效：若该原图还有**同署名**的有效商用授权 →
    自动递补，已有署名确认继续有效，下载不受影响；
  - 只有**不同署名**的有效授权 → 换用并置为「待确认署名」，展图停供；
  - 完全没有有效商用授权 → 标记「缺授权」，展图停供（不允许商用的授权不会被选用）。
  - 撤回落库**只改 `licenses` 表的一行**，实际改动行数与该授权被 1 张还是 1,000 张展图
    选用无关（见 `tests/test_revocation.py`）；读取路径不再按展图数量批量重写清单。
    事务任何一步失败整体回滚，原授权继续有效。
  - 授权页在撤回前会预演后果（自动递补 / 待确认新署名 / 缺授权）；
    连续同署名换证时，每次都沿用现有选证顺序递补到下一张同署名授权，无需重复确认。
  - 停供页面明确指出哪些原图缺授权、哪些需要确认新署名；再次撤回且找不到同署名备选时，
    提示会区分「停供缺有效商用授权」与「停供待确认新署名」。
- **编辑确认**：编辑在展图详情页核对当前清单（授权号为实时解析结果）并署名确认。
  确认在事务内重新校验：若清单中的授权在此期间被撤回或清单已变更（撤回与确认交错），
  拒绝确认、维持停供并提示重新核对；缺授权时确认无效，需先补录授权。
  确认记录与 CSV 下载使用同一授权号。
- **持久化**：全部状态存于 SQLite，撤回与确认交错、服务重启后，
  页面、API 与下载仍按同一规则解析出当前有效且已确认署名的清单。
- **页面**：`/` 展图列表与导入；`/exhibitions/{id}` 清单、停供原因、确认表单、确认记录；
  `/licenses` 授权列表（有效/已撤回/使用中）、撤回后果预演与撤回操作。
- **JSON API**：`GET /api/exhibitions`、`GET /api/exhibitions/{id}`、`GET /api/licenses`，
  便于数字展览团队程序化处理；`used_by` 为按实时选用结果统计的展图号列表。

## 自测

```bash
pip install -r requirements-dev.txt
python -m pytest tests/ -q
```

`tests/test_flow.py` 共 9 个用例，`tests/test_revocation.py` 共 6 个用例，全部通过：

1. 导入 → 未确认禁止下载(409) → 确认署名 → 下载清单内容正确；
2. 撤回授权后有同署名有效授权 → 自动换用，下载不受影响；
3. 撤回后只剩不同署名授权 → 停供并提示确认新署名 → 确认替代清单后恢复；
4. 唯一商用授权被撤回（仅剩非商用授权）→ 缺授权停供，确认不能恢复；
5. 重传含已撤回授权号的 CSV → 仍保持撤回，不恢复；
6. 撤回与确认交错（编辑提交过期清单）→ 拒绝确认、维持停供、提示重新核对 → 重新核对后确认恢复；
7. 服务重启后停供/确认状态保持，确认后下载使用当前有效清单；
8. 对照 CSV 重复导入幂等；
9. 三个页面正常渲染。

`tests/test_revocation.py` 覆盖换证专项：1 张与 1,000 张展图时撤回改动行数都为 1
（读取路径 0 写入）；连续同署名换证后页面/API/使用情况/确认/CSV 始终用当前授权号；
第二次撤回无同署名备选时区分「缺授权」与「待确认新署名」；撤回写入失败时回滚且原授权继续有效；
重启后继续按同一规则递补与停供。

另用 uvicorn + curl 手动试跑了「导入 → 确认 → 撤回（同署名递补/停供）→ 补录 → 再次撤回 →
重启服务」全流程；并单独测量了同一授权被 1 张 / 1,000 张展图选用时的撤回写入量（均为 1 行），
以及撤回与并发下载同时发生时的清单一致性（只见完整旧状态或完整新状态，无 5xx）。

## 未完成 / 说明

- 本环境没有 Docker，`docker-compose.yml` 与 `Dockerfile` 只做了静态校验，
  未实际构建镜像；应用本身已通过本地 uvicorn 全流程验证。
- 未做登录鉴权（编辑确认仅需填写姓名并留痕）；如需权限控制可前置反向代理或加登录模块。
- 不支持删除对照关系/展图，不支持撤销撤回（按需求撤回为终态）。
- 清单下载固定列「原图号、授权号、署名」，如需扩展字段可在 `download_manifest` 中调整。
